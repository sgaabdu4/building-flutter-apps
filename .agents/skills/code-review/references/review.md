# Review method

- Target = identify the requested artifact + comparison base. Use the supplied PR/base; otherwise resolve the branch's intended target from repository evidence. Upstream tracking alone may identify the same branch, not its merge target. Unclear scope → state the gap before drawing conclusions.
- Diff = read full hunks + affected owners/callers. Branch/PR → cumulative diff against its merge-base; commit → requested patch; working tree → staged + unstaged + in-scope untracked files. Include local changes in a branch review only when in scope. Empty diff → no changes to review, not a failed review.
- Intent = compare against the user's request, supplied/linked requirements and the project's `REQ-` rules in `docs/requirements.md`. Check missing behavior, changed contracts + unsupported additions; compatibility code for a shape that never shipped is one. Missing requirements → state that limit; do not infer intent from the implementation itself.
- Claims = trace the failure scenario through actual data, state, permissions, ordering or callers. For plans/diagnoses/proof, separate proposed behavior from implemented behavior and claimed results from observed results.
- Tests = apply [Test design + quality](../../he/references/testing.md) to affected tests and claimed proof. Passing gates do not establish requirement coverage, realistic UI behavior or deployed success. Removed test, row or assert that the plan says another test covers → break the code it guarded; that other test must fail, else finding.
- Hot paths = no [HE-HOT-PATH](../../he/references/requirements.md#he-hot-path) finding was hidden by code that still does the same work; apply [Hot paths + data layout](../../he/references/efficiency.md#hot-paths--data-layout) to changed loops, queries and handlers.
- Skill text = changed skill or reference prose → the plan or PR records a [Writing Great Skills](../../writing-great-skills/SKILL.md) Reader check on it, and each sentence the Reader quoted was reworded or moved; no record → finding.
- Visible change = judge the after screenshots against each [Usability](../../he-plan/references/ux.md) rule; one Pass/Fail line per rule in the review for all screenshots together, or an N/A line with the reason the rule does not apply; a rule that an image cannot show is judged from its test or code; a Fail is a finding; a missing after screenshot is a finding.
- Finding = precise location + code/evidence fact + triggering condition + concrete impact + smallest useful correction. Rank by impact and likelihood. Remove preference-only, duplicate, speculative and already-disproved candidates; an unresolved question is not a confirmed defect.
- Plan match = when the task has a PLAN.md, list every acceptance item as met or not met with its test/check result as proof; skip none. No plan → say so.
- Result = actionable findings first, then the Plan match, then material coverage limits + unverified checks. No findings → say so without implying unperformed verification or approval of unknown behavior.

# Building Flutter Apps Design

## Overview

The interface is agent guidance, plugin metadata, shell hooks and copied Flutter/Windows assets. There is no application UI; visual Atomic Design does not apply.

## Components

- `skills/building-flutter-apps/SKILL.md` routes to focused references and copied assets.
- `.claude-plugin`, `.codex-plugin`, `.agents/plugins` and `hooks/hooks.json` expose the supported Claude/Codex integrations.
- `hooks/scripts` reports architecture violations and project verification requirements.
- `tool` owns native routing, drift, Markdown, plugin and Windows asset assertions. `hard-eng.gates.json` invokes the existing repository checks.
- `.github/workflows/ci.yml` verifies the repository and upstream guidance drift; the separate Windows workflow proves real installer settlement for affected assets.

## Do's and Don'ts

- Keep package constraints in `references/core-stack.md` and conditional details in the linked skill references.
- Keep native hook failure behavior and clean/violating fixtures together.
- Preserve immutable upstream provenance and actual Windows runtime proof.
- Do not introduce application manifests or duplicate the existing check scripts to install repository tooling.
